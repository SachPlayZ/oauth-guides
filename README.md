# OAuth Runway

**How long until your users can connect App X through *your own* OAuth app, and what's in the way.**

Live: **https://oauth-runway-three.vercel.app** · Generating a Guide needs the demo passcode (shared in the submission notes, not here).

A developer building an agent on Composio starts with Composio's managed OAuth apps. Before launch, many need their own OAuth app: for their brand on the consent screen, custom scopes, their own quota, faster polling, or because the Toolkit has no managed app. Registering one takes minutes with GitHub. With Gmail it takes weeks, plus a paid security assessment. Provider docs explain the clicks, but they don't say up front how long it takes, what will block you, or what to do while you wait. OAuth Runway answers those questions first, and it says how sure it is.

## Try it

1. Open **[Gmail](https://oauth-runway-three.vercel.app/guides/gmail)**. Reading mail is **R4**, and the Gate table shows which requirement causes it, with evidence. Switch the usage row to *Send email only* and the security assessment drops out.
2. Open **[Slack](https://oauth-runway-three.vercel.app/guides/slack)**. OAuth is self-serve, but unlisted apps can read history only once a minute. That Blocking limit is what makes it R2.
3. Type any app name or URL into the directory search and hit **Generate**. You can watch the agent search, read pages and write the Guide (about 1–3 minutes).
4. Read **[/verification](https://oauth-runway-three.vercel.app/verification)** to see what the agent got wrong and what changed.
5. On any Guide, choose **Copy Markdown** and paste it into Claude Code. It includes a Setup agent block: what an agent may do for you, and where it must stop and hand back to you.

## What a Guide answers

| Question | Where |
|---|---|
| How hard? | **Runway level R0–R5**, per usage row (sign-in vs. reading data). It's a range (`R1–R4?`) when some Gate answers are unknown. |
| How long? | Hands-on effort, approval wait and cost, shown **separately** |
| What will bite me? | Gate table, requirements, Blocking limits, gotchas, "what we couldn't verify" |
| Who does what? | Each step has an owner: *Setup agent*, *Setup agent drafts / you confirm*, or *you* (sign-in, 2FA, terms, payment, final submit) |
| Where do I start? | **Start here**: the first step you own, with its link |
| Composio specifics | Exact callback URL, auth config steps, and a warning that existing connections are not migrated |

Every Claim carries an **Evidence label**:
- **Tested**: our own probe or attempt.
- **Documented**: official docs, with a quote.
- **Reported**: a third-party source.
- **Unverified**: inferred, or the quote wasn't found on the page.

Each Claim also has a source link and a checked date.

## How it works

```
query → 0 Resolve → 1 Probes ┐
                    2 Composio lookup ├→ 4 Quote check → 5 Verify → 6 Synthesize → 7 Score → save version
                    3 Research ┘
```

| Stage | What it does |
|---|---|
| 0 Resolve | Searches Composio Toolkits first, then one LLM web lookup. Ambiguous names ("Box", "Monday") show a picker; nonsense says "not found". A Guide newer than 30 days is reused. |
| 1 Probes | Plain `fetch` calls for OIDC / RFC 8414 discovery and portal reachability. Each result becomes a **Tested** Claim. |
| 2 Composio | Toolkit auth schemes and managed-auth availability; the hand-verified v3 callback URL |
| 3 Research | 5 parallel searches, up to 10 official pages read, and 4 parallel extraction calls. Each finding must cite a page and quote it. Every Gate question gets yes / no / not found. |
| 4 Quote check | Code confirms each quote appears on the fetched page. If it doesn't, the Claim becomes Unverified. |
| 5 Verify | A second model checks each Claim against its quote: supported, partial or unsupported. |
| 6 Synthesize | Two small calls: usage rows and verdict, then steps and gotchas. Code drops citations to Claims that don't exist. |
| 7 Score | **Code, not the LLM**, derives the level, range, confidence, effort and "Start here" |

Progress streams to the browser through job events, polled once a second, so a refresh doesn't lose the run. The run has a hard deadline of 240s; if research overruns, the Guide is written from what was found and confidence drops.

**Stack:**
- App: Next.js 16 (App Router) and Tailwind.
- Database: Postgres on Neon via Drizzle (`pg`, pooled).
- Models: Groq free tier (`gpt-oss-120b` → `qwen3.8-27b` → `gpt-oss-20b` fallback chain).
- Search: Tavily for search and page extraction.
- Hosting: Vercel.

A live Guide costs **$0** in model fees and about 8 Tavily credits (ADR-0004).

## Key decisions

| Decision | Why |
|---|---|
| Target the moment of **moving off Composio managed auth before launch** | That's when the pain hits. It keeps the Guide Composio-specific (callback URL, auth config, migration). |
| **Verdict first, steps second** | Steps already exist in provider docs. A timeline, the gates and a plan for the wait don't. |
| **Effort, wait and cost shown separately** | "2 hours + 4–6 weeks + an assessment fee" calls for different planning than "2 days of work". |
| **Level per usage row** | Google sign-in is R0; reading Gmail is R4. Same provider, different path. |
| **Level derived in code from 9 Gate questions** ([ADR-0001](docs/adr/0001-runway-level-derived-from-requirements.md)) | The LLM states facts with citations, and code turns them into a level. That makes levels explainable ("R4 because security assessment, claims g1, g2") and comparable across Guides. |
| **An unknown never reads as "easy"** | Each Gate is answered yes, no or unknown. An unknown widens the level into a range and drops confidence to low. |
| **Wait only comes from an official Claim** | Third-party blogs misquote review times (found in verification). No official source means the wait shows "Unknown". |
| **Any product, Toolkit optional** ([ADR-0003](docs/adr/0003-guides-for-any-oauth-product.md)) | Reviewers will submit unfamiliar apps. Refusing everything that isn't a Composio Toolkit would fail the brief. |
| **Depth over breadth**: 4 reviewed Guides plus live generation | The brief grades judgment about evidence, so verified depth beats 100 shallow pages. |
| **Guide versions are only ever added**; pages show the latest Reviewed one | A live run never overwrites hand-checked content. |
| **Live runs don't log into provider portals** | Too slow, needs credentials, and unsafe in a public demo. The Markdown export carries a Setup agent block so *your* agent can do it, stopping at sign-in, 2FA, terms and submit. |
| **Free tiers** (Groq + Tavily) ([ADR-0004](docs/adr/0004-groq-and-tavily-free-tiers.md)) | $0 per Guide. Groq's 8K tokens/minute limit shaped the "gather then extract" design and a token-aware scheduler. |

### Runway levels

| Level | Meaning | Raised by a "yes" to |
|---|---|---|
| R5 | Gated: weeks to never | partner application; manual approval at the provider's discretion |
| R4 | Security assessment | third-party security assessment (e.g. Google CASA) |
| R3 | Verification | business, publisher, domain or scope verification |
| R2 | Review | production access review; minimum installs; any Blocking limit |
| R1 | Self-serve with limits | any requirement (HTTPS redirect, admin consent, test-user cap, privacy policy…) |
| R0 | Instant | none of the above |

**Confidence** is computed over the Claims behind the default row's Gates:
- **High:** all are Tested or Documented, and all are supported by the verifier.
- **Low:** any is Unverified or conflicting, or any Gate is unknown.
- **Medium:** everything else.

## What was checked

[verification/LOG.md](verification/LOG.md) records 52 Claims across GitHub, Slack, Gmail, Notion and the shared Composio facts. Each was checked by hand against the official page:
- ✅ **25** confirmed
- ✏️ **16** corrected
- ⚠️ **8** partly right
- ❓ **3** couldn't verify

The agent drafts (`draft-v1`, `draft-v2`) and the reviewed `final.json` sit next to the log.

Main error patterns, and what changed:

| Pattern | Example | Fix → re-run |
|---|---|---|
| Marketplace listing treated as a production gate | Slack v1 = **R5** (reality: R2, a rate limit) | Prompt defines Production; listing review isn't a gate. Slack R5 → R3–R5?. **Partly fixed.** |
| Official docs labeled third-party | `docs.slack.dev` ≠ `slack.com` | Sibling-domain check in code. Documented Claims: Notion 2 → 15. **Fixed.** |
| Off-topic sources | Gmail cited Nest and IAP pages | Extract prompt scoped to this product. 9 → 3. **Mostly fixed.** |
| Review time taken from a blog | Slack "1–10 weeks" | The wait needs an official Claim (enforced in code). **Fixed.** |
| "Manual review" read as "gated" | Gmail = R5 | Gate reworded to "at the provider's discretion, no published criteria"; gates made per row. **Fixed.** |
| One-liner contradicts the Gates | Notion "no special gates" with every Gate unknown | Prompt rule. **Fixed.** |

Seed facts that turned out wrong:
- Composio's managed-auth polling minimum is **2 minutes**, not 15.
- Slack's Marketplace minimum is **10** workspaces, not 5.
- Slack's 2025 rate limit **doesn't** affect existing installs.
- Notion public connections need **no** review; only Marketplace listing does.

### Setup agent attempt: GitHub

[evidence/github/attempt.md](evidence/github/attempt.md) records the attempt on 2026-11-10. Claude Code drove the built-in browser and created a real GitHub OAuth app wired to Composio's callback. It took 2.5 minutes end to end, about 40 s of which was the developer's handover.

| Observed | Effect on the Guide |
|---|---|
| Registration completed instantly, with no review step | The "no" Gate answers now rest on a **Tested** Claim. Confidence went from low to **high**. |
| The developer had to take over three times: sign-in with 2FA (GitHub Mobile push), copying the client secret, and clicking Authorize | Matches the step owners. The agent never read the secret. |
| Unregistered redirect URIs are rejected, **including a sub-path** of the registered one; PKCE `plain` is rejected | Exact-match redirects and S256-only PKCE are now Tested |
| The consent screen says **"Authorizing will redirect to https://backend.composio.dev"** | New gotcha: users see Composio's domain unless you 302-forward from your own |
| New apps show "Created less than a day ago · Fewer than 10 GitHub users" | New gotcha: own the app from an org so users see a company name |
| The form now takes a list of up to 10 redirect URIs, with wildcard matching off and expiring tokens on by default | Older docs and screenshots show a single callback field |

### Stress tests

PLAN §20, run 2026-11-10 from `scripts/stress.ts`. No query crashed.

| Query | Type | Result | Level · confidence | Claims | Time |
|---|---|---|---|---|---|
| Pipedrive | long tail | Toolkit | R1–R5? · low | 19 | 74s |
| Calendly | long tail | Toolkit | R1–R5? · low | 22 | 70s |
| Xero | long tail | Toolkit | R1–R5? · low | 25 | 83s |
| Typeform | long tail | Toolkit | R0–R5? · low | 13 | 107s |
| Canva | well-known | Toolkit | R3–R5? · low | 25 | 66s |
| Strava | not a Toolkit | web resolve, `composio: null` | R2–R5? · low | 18 | 104s |
| Monday | ambiguous name | exact Toolkit match | R1–R5? · low | 24 | 102s |
| Tavily | API-key Toolkit | **bug found → fixed**, re-run | R1–R5? · low | 9 | 72s |
| notion.so | URL | Notion Toolkit | R1–R5? · low | 13 | 95s |
| https://linear.app | URL | **picker (Linear vs Linear MCP) → fixed**: resolves to Linear | — | — | — |
| asdfgh | nonsense | "Couldn't identify this app" | — | — | 8s |

- **Run time:** median 83s, p90 107s (9 generations).
- **Per Guide:** 8–11 model calls, 5 searches and 4–10 pages read. That's about 7 Tavily credits, and $0 in model fees.
- **What it showed:** unreviewed Guides come out honest but wide. Every one is a range with low confidence, because official docs rarely answer every Gate question. That's the intended failure mode (an unknown never reads as easy), but it means reviewed Guides carry the real value.
- **Bugs found and fixed:**
  - Composio lists `composio.dev` as the app URL for some Toolkits (Tavily, Discord, Google Ads). Probes then found Composio's own OIDC server and labeled it "Tested". Those URLs are now ignored and the domain comes from a web lookup.
  - Two Toolkits sharing a domain (linear, linear_mcp) sent a URL query to the picker. Now the one named like the domain wins.
  - An API-key-only Toolkit claimed "you need your own OAuth app". Fixed.

## Limitations

- **Only one Setup agent attempt (GitHub).** For Slack, Gmail and Notion, step owners and handoff points come from documented flows, not observed runs, and "Tested" means deterministic probes only. No approval was completed.
- **Durations are what providers state.** There's no data on observed approval times, and no approvals were completed.
- **Generated Guides are unreviewed**, and the agent still makes mistakes: invented usage rows, and an occasional default row with unsettled Gates. Low confidence and level ranges make this visible, but don't prevent it.
- **JavaScript-rendered docs** sometimes can't be read or quote-checked, which lowers confidence.
- **Guides go stale.** Each one shows "last checked"; nothing re-runs automatically.
- **Free-tier limits**: Groq allows 8K tokens/minute per model, and Tavily allows 1,000 credits/month. Generation is behind a passcode and capped at 5 runs/hour per IP and 30/hour overall.

## Setup

You need Node 22, pnpm and Docker (or a Neon database).

```bash
pnpm install
cp .env.example .env.local   # fill in GROQ_API_KEY, TAVILY_API_KEY, COMPOSIO_API_KEY, DEMO_PASSCODE
pnpm db:up                   # local Postgres on :54329, or set DATABASE_URL to Neon
pnpm db:push                 # create tables
pnpm tsx scripts/seed-library.ts   # 100 Toolkits into the directory (uses data/library.json if Composio is unreachable)
pnpm tsx scripts/load-curated.ts   # the 4 reviewed Guides
pnpm dev
```

All three API keys have free tiers. Every external call happens server-side.

Other scripts:
- `pnpm test`: rubric, quote check, excerpt and resolve tests.
- `pnpm tsx scripts/try-generate.ts "Pipedrive" --save`: generate a Guide from the CLI.
- `pnpm tsx scripts/stress.ts --save <queries…>`: stress run with timings.
- `pnpm tsx scripts/check-curated.ts`: validate the curated JSON.

Layout:
- `lib/agent/`: the pipeline stages.
- `lib/rubric.ts`: levels, confidence and effort.
- `lib/schema.ts`: the Guide format.
- `data/curated/`: the reviewed Guides.
- `verification/`: drafts, finals and LOG.md.
- `docs/adr/`: decisions.
- `GLOSSARY.md`: terms.
